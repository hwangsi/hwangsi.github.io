개인정보처리방침 — 청구 데스크 (Edge 확장)

시행일: 2026-09-28 · 확장 버전 0.6.11 (이전판: 2026-08-11 · 0.2.0) · English below

「청구 데스크」(이하 "본 확장")는 분당서울대병원 연구관리시스템(MSRI, msri2.snubh.org)에서 연구비 지급신청의 영수증 기반 입력을 보조하는 개인용 도구입니다. 본 방침은 본 확장이 어떤 데이터를 다루는지 사실대로 밝히기 위한 것입니다.

요약 — 개발자 서버는 없습니다. 기기 밖으로 나가는 데이터는 이용자가 직접 켜는 두 기능뿐입니다: ① Anthropic API(영수증 판독·회의내용 문안, 이용자 본인의 API 키) ② 로그 업로드(이용자 본인의 Google 계정에 이용자가 직접 배포한 수신기로, 이용자 본인의 Google Drive 에 저장). 둘 다 쓰지 않으면 본 확장은 MSRI 화면 외에 어떤 외부 통신도 하지 않습니다.

1. 개발자가 수집하는 정보 — 없음

본 확장에는 개발자 서버가 존재하지 않습니다. 개발자는 이용자의 어떤 데이터도 수집·수신· 저장·판매하지 않으며, 분석 도구·광고·추적 코드를 포함하지 않습니다. 원격 코드를 내려받아 실행하지 않고, 모든 코드는 설치 패키지에 동봉되어 있습니다. 아래 3항의 전송도 개발자를 거치지 않습니다.

2. 기기에만 저장되는 정보

아래 정보는 브라우저의 chrome.storage.local 에 이용자 기기에만 저장되며, 3항에서 이용자가 켠 기능을 제외하고는 외부로 전송되지 않습니다. 기기·프로필 간에 동기화되지 않습니다.

3. 외부로 전송되는 정보 — 이용자가 켠 기능만

3-1. Anthropic API (https://api.anthropic.com) — 이용자가 실행할 때만

기능보내는 것보내지 않는 것
영수증 판독이용자가 선택한 영수증 파일, 추출 지시문로그인 정보, 화면 캡처, 과제 정보, 참석자
회의내용 문안이용자가 적은 회의목적, 과제명, 회의장소, 참석 인원 수, 작성 지시문참석자 이름·소속, 영수증, 금액, 계좌·주소
  • 전송은 이용자 본인이 입력한 Anthropic API 키로 이루어지며, 청구 주체도 이용자 본인입니다.
  • 개발자는 이 통신을 중계하지 않으며 그 내용에 접근할 수 없습니다.
  • 전송된 데이터의 처리는 Anthropic 의 정책을 따릅니다: www.anthropic.com/legal/privacy
  • 영수증에는 카드번호 일부 등 민감할 수 있는 정보가 포함될 수 있으므로, 소속 기관의 정보보호 정책을 확인한 뒤 사용 여부를 판단하시기 바랍니다. 이 기능을 쓰지 않고 값을 직접 입력할 수 있습니다.

3-2. 로그 업로드 — 이용자가 설정한 경우만, 이용자 본인의 Google Drive 로

본 확장은 실행 기록을 이용자가 다른 PC 에서도 확인할 수 있도록, 이용자가 본인의 Google 계정에 직접 배포한 Google Apps Script 웹 앱(수신기)으로 기록을 보낼 수 있습니다. 기본값은 꺼짐이며, 이용자가 패널에 수신기 설정 줄을 붙여 넣고 [연결 시험]으로 권한을 허용해야만 켜집니다.

  • 보내는 곳: 이용자가 배포한 https://script.google.com/macros/s/…/exec (Google 이 응답을 https://script.googleusercontent.com 으로 넘겨 주므로 두 주소 모두 사용). 받은 기록은 이용자 본인의 Google Drive(청구데스크_로그/ 폴더와 색인 시트)에 저장됩니다. 개발자는 이 수신기·Drive 에 접근할 수 없습니다.
  • 보내는 것: 각 실행의 단계별 진행 로그, 실행 시작 기록, 청구 입력 명세(과제번호·과제명·청구 유형· 금액·상호·일자·회의 정보·참석자 이름과 소속), 실행 환경 값(브라우저 버전·언어·시간대, CPU 코어 수·메모리 크기, 창·화면 크기, 배율, 글꼴 크기, 이용자가 정한 PC 표시명), 확인 시점의 화면 캡처(가린 것만).
  • 가림: 계좌번호·주민등록번호·주소 등 개인정보는 보내기 전에 로그에서 지우고, 캡처에서는 검게 가립니다. 가리지 않은 캡처는 보내지 않습니다(가림에 실패하면 그 캡처는 보내지 않고 기기에만 남습니다). API 키·수신기 토큰·로그인 정보는 어떤 기록에도 싣지 않습니다.
  • 보호: 수신기는 무작위 토큰이 맞는 요청만 받고, 쓰기만 합니다(목록·읽기 기능이 없음). 하루 용량 상한이 있습니다.
  • 끄기: 패널에서 설정 줄을 [지우기] 하거나, Edge 확장 설정에서 두 주소의 사이트 권한을 거두면 즉시 멈춥니다. 이미 Drive 에 올라간 기록은 이용자가 Drive 에서 직접 삭제합니다.
  • Google 의 데이터 처리는 Google 개인정보처리방침을 따릅니다: policies.google.com/privacy

3-1·3-2 를 쓰지 않으면 본 확장은 MSRI 화면 외에 어떤 외부 통신도 하지 않습니다.

4. 로그인 정보

본 확장은 이용자의 아이디·비밀번호를 요구하거나, 입력하거나, 저장하지 않습니다. 이용자가 브라우저에서 이미 로그인한 세션 위에서 동작할 뿐이며, 로그인 화면에 값을 입력하는 동작은 코드 차원에서 차단되어 있습니다. 세션이 만료되면 작업을 중단하고 이용자에게 재로그인을 요청합니다.

6. 데이터 삭제

  • 로컬 저장 데이터: Edge 에서 본 확장을 제거하면 함께 삭제됩니다. 패널의 설정에서 개별 삭제도 가능합니다.
  • 다운로드 폴더의 기록·캡처: 이용자가 직접 삭제합니다.
  • 로그 업로드로 올라간 기록: 이용자 본인의 Google Drive(청구데스크_로그/)에서 직접 삭제합니다.
  • 개발자가 보관하는 데이터는 없으므로 개발자에게 삭제를 요청할 대상이 존재하지 않습니다.

본 확장은 특정 기관의 내부 업무를 위한 도구이며 만 14세 미만 아동을 대상으로 하지 않습니다.

Privacy Policy — Claim Desk (Edge extension)

Effective: 2026-09-28 · Extension version 0.6.11 (previous: 2026-08-11 · 0.2.0)

Claim Desk ("the extension") is a personal productivity tool that assists with receipt-based expense entry in a hospital-internal research administration system (MSRI, msri2.snubh.org).

Summary — There is no developer server. Data leaves your device only through two features that you turn on yourself: (1) the Anthropic API (receipt reading and meeting-minutes drafting, with your own API key) and (2) log upload (to a receiver you deploy in your own Google account, stored in your own Google Drive). If you use neither, the extension communicates with nothing but the MSRI site.

1. Information collected by the developer — none

There is no developer-operated server. The developer does not collect, receive, store, or sell any user data. The extension contains no analytics, advertising, or tracking code, and executes no remotely hosted code — all code ships inside the package. None of the transfers in §3 pass through the developer.

2. Information stored on your device only

The following is stored in chrome.storage.local on your device only and is not transmitted except by the features you enable in §3. It does not sync across devices or profiles: project records (project number, name, type), settings (your Anthropic API key, model choice), saved meeting-attendee presets, a history of entries made with the extension, the log-upload receiver address and access token (only if you set up §3.2), an outbox of logs not yet uploaded because of a network error (at most 8 items / 3 MB, removed once uploaded), and the tab zoom level to restore after a run. Screenshots and logs produced during a run are saved to your Downloads folder (청구데스크/) and remain on your computer (if §3.2 is on, masked copies also go to your own Drive).

3. Information sent off your device — only features you turn on

3.1 Anthropic API (https://api.anthropic.com) — only when you invoke it

  • Receipt reading sends the receipt file you select and an extraction prompt. It does not send credentials, screenshots, project data, or attendees.
  • Meeting-minutes drafting sends the meeting purpose you typed, the project title, the meeting place, the number of attendees, and a drafting prompt. It does not send attendee names or affiliations, receipts, amounts, account numbers, or addresses.

Requests are made with your own Anthropic API key and billed to you. The developer does not proxy them and cannot access their contents. Anthropic's handling is governed by www.anthropic.com/legal/privacy. Receipts may contain sensitive details such as partial card numbers, so please check your organization's information-security policy; you can type values by hand instead.

3.2 Log upload — only if you set it up, to your own Google Drive

So that you can review run records from another PC, the extension can send them to a Google Apps Script web app that you deploy in your own Google account. It is off by default and turns on only after you paste the receiver's configuration line into the panel and grant the site permission via [Test connection].

  • Destination: your own https://script.google.com/macros/s/…/exec (Google hands the response over via https://script.googleusercontent.com, so both hosts are used). Records are saved in your own Google Drive (a 청구데스크_로그/ folder and an index spreadsheet). The developer has no access to your receiver or your Drive.
  • What is sent: the step-by-step log of each run, a run-start record, the claim specification that was entered (project number and title, claim type, amount, merchant, dates, meeting details, attendee names and affiliations), run-environment values (browser version, language and time zone, CPU core count and memory size, window and screen size, zoom, font size, and a PC label you choose), and masked screenshots taken at confirmation points.
  • Masking: account numbers, resident registration numbers, addresses and similar personal data are removed from logs before sending and blacked out in screenshots. Unmasked screenshots are never sent — if masking fails, that screenshot stays on your device only. API keys, the receiver token and login credentials are never included in any record.
  • Protection: the receiver accepts only requests carrying a random token and is write-only (it has no list or read function). A daily size cap applies.
  • Turning it off: clear the configuration line in the panel, or revoke the site permission for the two hosts in Edge's extension settings; uploads stop immediately. Records already uploaded are deleted by you in your Drive.
  • Google's handling is governed by policies.google.com/privacy.

If you use neither §3.1 nor §3.2, the extension makes no outbound requests other than to the MSRI site.

4. Credentials

The extension never requests, enters, or stores your username or password. It operates on top of a session you have already signed into, and filling login fields is blocked at the code level. If the session expires, the extension stops and asks you to sign in again.

5. Why each permission is requested

debugger — the target application (SmartClient) contains widgets that respond only to trusted input events, so standard DOM manipulation cannot drive them. It is used to dispatch input events, attach the receipt file you selected to the upload field, capture confirmation screenshots, and read the page zoom; it is attached only to a msri2.snubh.org tab and only during a task, and is never used to inspect or log network traffic. host_permissions: msri2.snubh.org — the screen being automated. host_permissions: api.anthropic.com — §3.1. optional_host_permissions: script.google.com, script.googleusercontent.com — §3.2; optional, so it is not requested at install time but only when you press [Test connection]. storage — §2. scripting, sidePanel — the side-panel UI and page-state checks. downloads — saving run records and screenshots to your Downloads folder.

6. Deleting your data

Removing the extension from Edge deletes its local storage; individual items can also be cleared from the panel's settings. Files in your Downloads folder are deleted by you. Uploaded records (§3.2) are deleted by you in your own Google Drive. The developer holds no data, so there is nothing to request deletion of.

7. Audience

The extension is a tool for internal work at a specific institution and is not directed to children under 14.

8. Changes

If this policy changes, this document is updated with a new effective date, and material changes to data handling are announced with the extension update.
